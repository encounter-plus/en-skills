# Изображения: быстрая загрузка без потери смысла задания

В местах проведения игр мобильная связь бывает слабой или отсутствует. При вычитке уровня/игры проверяйте вес изображений в задании, подсказках, бонусах и раскрываемых блоках. Уменьшенная CSS-ширина не уменьшает загружаемый файл. Цель — снизить объём передачи при сохранении читаемости и механики, а не получить минимальное число байт любой ценой.

## Порядок проверки

1. Соберите изображения и их места использования, включая img/srcset, фоновые картинки и появляющиеся после скриптов. Не исполняйте произвольные скрипты ради поиска ссылок. Отделите реально загружаемые варианты от альтернатив srcset; одинаковый ресурс учитывайте один раз в сумме, но укажите все места. Не гарантируйте кэширование и доступность офлайн.
2. Для доступных оригинальных файлов измерьте байты, формат, разрешение, число кадров/страниц и прозрачность. Размер из заголовка HTTP помечайте как заявленный, размер скачанного файла — как измеренный. DOM naturalWidth/Height дают разрешение, не вес; нулевой transferSize не доказывает маленький файл. Если хост не может получить файл, поставьте not-checked и попросите оригинал или доступный замер. Не угадывайте мегабайты по скриншоту.
3. Выясните назначение. Гигарама, поиск мелких деталей, пиксельные загадки, стеганография, метаданные, прозрачность и последовательность кадров могут быть частью решения. Для таких изображений сохраняйте оригинал и детали; предложите облегчённое превью с отдельным оригиналом только если это не меняет механику и автор согласен. Не объявляйте высокий вес ошибкой сам по себе.
4. Для обычной фотографии предложите пробную копию JPEG/WebP, для текста/схем/резких линий — PNG или иной проверенный вариант с читаемостью. PNG-фотография часто допускает большой выигрыш при JPEG, но это надо измерить. JPEG не поддерживает прозрачность; фон при преобразовании выбирается явно. Формат должен поддерживаться целевым хостингом и браузерами игроков.
5. Практический начальный кандидат для обычной фотографии: длинная сторона 1600 px и JPEG quality 82, затем сравнение. Это не обязательный стандарт. Сигналы для дополнительного просмотра: файл больше 500 КиБ или сторона больше 1920 px; много меньших файлов тоже могут дать тяжёлый уровень. При малом исходнике не увеличивайте его. Lossy-конвертация не гарантирует отсутствие потерь: проверьте надписи, коды, цвета и значимые детали на телефоне и в необходимом масштабе.
6. В отчёте покажите уровень/блок, источник, назначение, исходный формат/байты/размеры, предложенную копию с теми же измерениями, экономию в байтах и процентах, а также исключения и непроверенные ресурсы. Суммарный объём доступных уникальных файлов — оценка нагрузки, не точное время загрузки. При отсутствии выигрыша не рекомендуйте замену ради веса.

При запросе только анализа выдавайте рекомендации. Создание копии по запросу автора не означает разрешение загрузить её в движок. Сохраните оригинал; заменяйте ссылки лишь отдельным разрешённым действием после проверки копии. Повторная JPEG-перекодировка накапливает потери — работайте от оригинала.

## Реальный локальный инструмент en-skills

При установленном npm runtime доступны CLI `en-image` и экспортируемые функции `inspectImage`, `transformImage`, `readLocalImage`, `transformImageFile`. Отдельная установка текста скилла не устанавливает runtime. В браузерной обвязке эти Node-команды не появляются автоматически: используйте только объявленные хостом инструменты.

```sh
en-image inspect --input original.png
en-image convert --input original.png --out optimized.jpg --format jpeg --max-width 1600 --max-height 1600 --quality 82
en-image convert --input transparent.png --out optimized.webp --format webp --max-width 1200 --quality 82
en-image convert --input diagram.png --out optimized.png --format png
```

В checkout: `npm run en-image -- inspect --input original.png`; после сборки: `node dist/image-cli.js ...`. CLI пишет JSON в stdout, ошибки в stderr, код ошибки 1. Обработка локальная, файлы по URL не скачиваются, ничего в игру не загружается. `inspect` читает метаданные, не подтверждает целостность всех пикселей или художественное качество.

- Чтение растров JPEG, PNG, WebP, GIF, TIFF, AVIF/HEIF при поддержке декодера установленной сборки. Выход: JPEG, PNG, WebP. SVG и многостраничная/анимированная конвертация не поддерживаются; кадры не отбрасываются молча.
- `--max-width`/`--max-height` задают ограничивающий прямоугольник без обрезки и растяжения, пропорции сохранены, увеличения нет. Если границы не заданы, разрешение сохраняется. EXIF-ориентация применяется перед изменением размеров.
- JPEG/WebP по умолчанию quality 82, диапазон 1–100. PNG — сжатие без потерь при кодировании, без палитры; ресайз всё равно меняет пиксели. quality для PNG отклоняется.
- Для JPEG с альфа-каналом нужен явный `--background '#ffffff'` (или выбранный цвет #RRGGBB), иначе инструмент откажет. PNG/WebP сохраняют прозрачность.
- Метаданные обычно удаляются; `--preserve-metadata` сохраняет поддержанные метаданные, но не гарантирует побайтового совпадения файла. `--detail-critical` блокирует преобразование защищённого изображения. Для загадок в метаданных/пикселях храните исходник, даже lossless перекодирование файла может изменить скрытые данные.
- Лимиты локального инструмента: 50 МиБ и 60 млн пикселей, размер стороны параметра 1–32768. Это пределы обработки, а не требования игры. Гигарамы сверх лимита не пытайтесь автоматически уменьшать или обходить защиту.
- `--out` обязателен для конвертации; расширение должно соответствовать формату. Существующие файлы и оригинал не перезаписываются. Результат может оказаться больше исходника: JSON явно показывает `smaller`, `savedBytes`, `savedPercent` и требует визуального сравнения. `applied: false` означает, что игра не менялась.

## Передача результата в карточку хоста

Если хост предоставляет resize_image и карточки ДО/ПОСЛЕ, после вызова инструмента карточка создаётся автоматически из результата обработки. Не просите автора выгружать, прикреплять или переносить JSON. Результат содержит исходник и копию, измеренные bytes/width/height/format; хост сохраняет файлы локально и показывает обе картинки и экономию. Успешное создание карточки означает только готовность локальной копии, не загрузку в движок.
