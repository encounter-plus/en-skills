# Авторские скрипты: поддержанная основа

Область: **modern gameplay / EN+ Kotlin**. Host выбирает этот контракт для demo.en.cx. Для legacy/RN используйте [legacy browser](scripting/legacy-browser.md) и [RN](scripting/legacy-enplus-react-native.md); гарантии window.EN ниже на них не распространяются.

При проектировании интерфейса применяйте [приоритет экранов по типу игры и поверхности](author-ui-policy.md).

[Контракт window.EN v1](engine-task-contract.md) описывает API авторских скриптов. [HTML-оболочка и стили классического движка](engine-browser-shell.md) сохранены как исторические assets. Для проверки сайта используйте настоящую /preview по [инструкции запуска](script-harness.md). API устанавливается перед author scripts. Доступны version, ready, getState, subscribe, serverTime, urls, answer, bonus, takeHelp. До генерации конкретных обращений к полям состояния получите полный актуальный контракт или fixture: этот краткий список не определяет все DTO и сигнатуры.

Для данных и действий предпочитайте window.EN. State snapshots неизменяемы; результат ответа nullable: null не означает неверный код. Для времени используйте серверную базу. Смена уровня и повторная отрисовка не должны оставлять дубли подписок, таймеров и действий.

EN+ не предоставляет встроенный jQuery или старый engine JSON proxy. Анонс — авторский HTML-блок на странице игры `/games/{gameId}`; в приложении ему соответствует полное описание игры. Поддержка HTML авторов в полном описании игры не означает, что там есть та же игровая API-поверхность, что в gameplay.

Анонс размещается в блоке «От автора игры», внутри `.en-user-html`. Этот класс встречается и у других авторских блоков страницы, поэтому для выбора анонса учитывайте его контейнер. Доступность `window.EN` и выполнение JS в анонсе проверяйте отдельно: поддержка HTML/CSS сама по себе не подтверждает поддержку произвольных скриптов.

DOM gameplay: .content содержит h2[data-en="level-title"], за которым расположен [data-en="tasks"] с .engine-task; task_id задаёт id="task-…" и data-task-id. Это EN+-совместимость с классическими селекторами, а не обещание одинакового DOM всех браузерных клиентов.

Ответная форма проходит через нативное действие. Асинхронный валидатор должен отменить исходный submit синхронно, иначе возможна двойная отправка. form.submit() и EN.answer()/EN.bonus() — прямые действия без повторного submit. Не подменяйте native input геометрию, фокус или IME предположениями о DOM.

Внешний fetch требует собственного контракта доступа и req_id для engine JSON-action. Не вставляйте author/admin JWT в script. Реальный API недоступен — используйте синтетический mock, а не скрытый запрос в производственную игру.

Проверки: первичная загрузка; повторная инициализация; смена уровня; получение snapshot; null verdict; медленный ответ; отсутствие сети; снятие обработчиков; узкий экран; browser и Android WebView. Отдельно укажите, что проверено автоматически и что требует устройства. Не обещайте совместимость приложения по одному браузерному тесту.
