# Рабочая папка и память игры

Одна папка соответствует одной игре. Git и конкретный harness не обязательны. en-skills определяет структуру, шаблон и миграции; host создаёт папку и хранит подключения отдельно. Чаты могут оставаться в хранилище host: переносимые материалы игры находятся в файлах.

Для правок Google Docs/Sheets в любом процессе применяй [обязательное одобрение перед браузерным редактированием](google-documents.md).

## Начало и завершение работы

Перед работой в папке игры через любой скилл, включая прямой вызов `game-import`, прочитай `GAME.md`, `decisions.md` и `tasks.md`. Затем загружай материалы выбранной задачи или уровня. Backlog читай при планировании, архив — при поиске конкретной истории. Если папки или файловых инструментов нет, явно укажи, что память не сохранена; установка скилла сама по себе не создаёт рабочую папку.

Сверь целевую игру с `GAME.md` до записи в движок. Неизвестные поля дополни установленными из запроса автора или проверенного источника фактами: название, движок, домен, ID, тип и ограничения. Укажи источник сведений. При конфликте известных идентификаторов уточни цель; неизвестные значения и предположения не превращай в факты. Сохрани уже известную привязку до длительного импорта: ошибка последующей операции не должна терять контекст игры.

После согласованного изменения обнови соответствующие материалы и статусы задач. В `GAME.md` храни общую картину и актуальное состояние, в `decisions.md` — подтверждённое решение, дату, источник согласования и заменяемое решение. Источники и результаты импорта связывай с материалами уровней; частичное выполнение и блокеры отражай в `tasks.md`. Предложения помечай как предложения; обсуждение не считается согласованием публикации в движок. Пароли, токены и cookies хранятся у host, а не в памяти игры.

Перед изменением перечитай файл: другой чат мог его обновить. Объедини независимые правки; конфликтующие решения вынеси автору. Сохраняй происхождение данных и буквальные коды/ответы. После записи перечитай изменённые файлы и проверь факты, ссылки и сохранность чужих правок. В итоговом ответе укажи сохранённые файлы либо конкретную причину, почему сохранить не удалось. Работа с памятью завершена, когда подтверждённые сведения записаны и проверены; один ответ в чате этого не заменяет.

## Структура версии 1

| Путь | Назначение |
|---|---|
| `AGENTS.md` | Краткий порядок чтения памяти для нового чата |
| `GAME.md` | Название, движок, домен, ID, тип, ограничения и текущее состояние игры |
| `decisions.md` | Подтверждённые решения и история их замены |
| `tasks.md` | Текущая работа: активные задачи, ближайшие согласованные шаги и блокеры |
| `planning/backlog.md` | Предложения и отложенные задачи; создаётся при появлении таких записей |
| `archive/tasks/YYYY-MM.md` | Завершённые и отменённые задачи по месяцу закрытия; создаётся при первом переносе |
| `sources/` | Исходные материалы с URL/файлом-источником и датой получения |
| `levels/` | Материалы уровней, создаваемые по необходимости |
| `artifacts/` | HTML, изображения и другие результаты для просмотра |
| `.en-agent/project.json` | Версия шаблона и локальный UUID; технические метаданные host |

Для импортированного уровня используй устойчивый ID движка в имени каталога, например `levels/12345/`. Для нового черновика до получения ID — `levels/draft-<local-id>/`; соответствие новому ID фиксируй явно. Порядковый номер уровня не является его идентификатором. Папки уровней создаются при появлении материалов.

Датированные снимки движка храни в `sources/`, указывая полноту и момент чтения. Снимок не доказывает текущее состояние сервера. Общий контекст держи кратким; подробные условия и источники относятся к конкретному уровню.

## Фотографии для проверки кодов

При сборе изображений различай две категории по назначению:

| Категория | Назначение и рекомендуемое хранение |
|---|---|
| Изображения задания | Картинки и фотографии, предназначенные для показа игрокам в задании или подсказке. Храни в `levels/<устойчивый-id>/assets/`, до привязки к уровню — в `sources/task-assets/`. Их содержание и место показа относятся к процессу level-author. |
| Авторские фото локации и отписки | Общие планы локации, ориентиры, места нанесения и крупные планы кодов для подготовки и проверки игры. Храни в `levels/<устойчивый-id>/photos/`, до привязки к уровню — в `sources/photos/`. game-author и check-code-photos ссылаются на одни исходники этой категории. |

Для черновика используй `levels/draft-<local-id>/` вместо каталога ID движка. Подпапки создаются по мере появления материалов; отдельная копия для каждого скилла не нужна. Рекомендуй сохранить все авторские фото локации и отписки в соответствующей папке. Существующую раскладку сохраняй, фиксируя категорию у ссылок; смешанная папка не делает все изображения материалами проверки кодов.

Определяй назначение по запросу и материалам автора, а не по расширению файла или наличию надписи на картинке. Если назначение неясно, спроси: «Это изображение для задания игрокам или авторское фото локации/отписки для проверки?» Авторские фото сами по себе не являются вложениями задания: включай их в задание или подсказку только при согласованном назначении для игроков. Если одно фото используется в обеих ролях, явно зафиксируй обе роли и место показа, сохраняя ссылку на исходник.

Сначала используй уже переданные вложения и известный путь из материалов игры. Если источник фото ещё неизвестен, спроси: «В какой папке находятся фотографии кодов? Можно сохранить их в `sources/photos/` или папке уровня `levels/<id>/photos/` и указать путь, либо отправить фото прямо в чат». Существующую папку автора тоже можно использовать: зафиксируй её путь в материалах соответствующего уровня или задачи, не требуя переноса. Если папка недоступна инструментам хоста, попроси отправить фото в чат; наличие пути само по себе не означает, что фото просмотрены. Проверка вложений доступна и без рабочей папки игры.

При сохранении вложений используй доступные файловые инструменты хоста и выбранную общую структуру; сохраняй оригиналы без перезаписи одноимённых файлов. Если сохранить вложения невозможно, явно укажи это и предложи автору сохранить их самостоятельно. В материалах уровня или задачи фиксируй ссылки на исходники, известную привязку к уровню/сектору и отчёт проверки. Неизвестную привязку уточняй; чтение с фото, ожидаемый код из документа и принимаемые движком ответы сохраняй раздельно. При переходе между скиллами передавай эти ссылки и уже известную привязку, чтобы не запрашивать фото повторно.

## Текущие задачи, backlog и архив

Задача здесь — работа автора, уровень — игровой материал. Одна задача может относиться к уровню или ко всей игре. Веди запись о результате работы, а не о каждом действии агента.

1. Перед добавлением проверь текущий список и, при необходимости, найди связанную запись по ID или теме в backlog/архиве. Обновляй существующую задачу. Новая получает устойчивый уникальный ID, например `T-20261021-a7f2`; сохраняй его при переносе и повторном открытии.
2. В `tasks.md` держи по одной краткой записи: ID, статус, ожидаемый результат или ближайший шаг, блокер при наличии и ссылка на подробности. Ориентир — до 30 задач и 100 строк. При превышении вынеси детали и отложенную работу; действительно активные задачи и блокеры сохраняй видимыми, даже если ориентир превышен.
3. Подробности уровня храни в `levels/<устойчивый-id>/`, общие материалы задачи — при необходимости в `planning/<task-id>.md`. Ссылки между файлами делай относительными к содержащему их файлу. В текущем списке достаточно ссылки; переписку и большие чек-листы туда не копируй.
4. Предложения и отложенные задачи помещай в `planning/backlog.md`, явно различая предложение и согласованную отложенную работу. При выборе следующего этапа переноси нужную запись в `tasks.md`, сохраняя ID и статус согласования. Храни одну актуальную запись задачи, а не две независимо редактируемые копии.
5. После проверки результата перенеси закрытую задачу в `archive/tasks/YYYY-MM.md`: ID, итоговый статус, дата закрытия, краткий результат и ссылка на проверку или материалы. Для отмены укажи причину. Сначала сохрани запись в архиве и проверь ссылки, затем убери её из текущего списка. При повторном открытии сохрани архивный результат, отметь возобновление и верни тот же ID в текущую работу.
6. Создавай backlog, архив и их каталоги только при появлении содержимого. В `tasks.md` добавляй ссылки на них только после создания. Для обращения к большой истории сначала ищи ID или тему, затем читай найденный раздел. После обновления проверь, что текущий список отражает ближайшую работу, закрытые результаты сохранены, ссылки доступны и правки других чатов не потеряны.

Подтверждённые решения по игре остаются в `decisions.md`; задача ссылается на решение вместо его копирования. Это правила работы агента с файлами, а не фоновый сервис архивирования.

## Инициализация и обновление

Версионированный шаблон и исполняемый initializer находятся в ресурсах skill `game-author`. Host вызывает initializer установленной версии en-skills; он создаёт файлы только в новой/пустой папке. Повторный вызов в уже созданной игре сохраняет существующие файлы, включая авторские изменения. Чужая непустая папка требует отдельного импорта.

Обновление en-skills не заменяет файлы игр. Изменение версии шаблона требует явной миграции с резервной копией и проверкой результата; пока поддержана только версия 1, другая версия блокирует инициализацию. Подключения, ключи, cookies и исполняемые файлы harness хранятся вне игры.

Разделение задач совместимо со структурой версии 1: новые игры получают краткий текущий список без пустых backlog/архива. В существующей игре применяй правила при следующем обновлении задач, сохраняя записи и авторские правки; повторная инициализация их не переписывает.

Проверка контракта: две игры имеют разные UUID; новый чат получает контекст только своей папки; повторная инициализация сохраняет авторский текст; неизвестная версия и символические ссылки отклоняются.
