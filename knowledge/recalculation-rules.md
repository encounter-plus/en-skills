# Правила и вход расчёта

`calculateRecalculation(evidence, rule)` и CLI используют один детерминированный модуль. Все величины — секунды; события содержат ISO timestamps с явным timezone. Среднее сохраняет сумму и делитель. Дробное время требует `rounding: "floor" | "ceil" | "nearest"`; без выбора (`exact`) строка остаётся unresolved. `nearest` — округление положительных длительностей к ближайшей секунде, половины вверх.

Общие поля rule: стабильный ASCII `id` инцидента, `reason`, при необходимости `participants` (например `team:123`), `existingCorrectionIds` для подтверждённых прежних правок этого инцидента. Host хранит связь incident ID с проверенными correct IDs в приватном журнале и добавляет их в следующий расчёт. В CLI передавайте тот же `--store` в calculate/propose/approve/apply; библиотечный caller передаёт existingCorrectionIds явно. Сохраните incident id при повторном расчёте. В игровом comment остаётся ровно причина автора, без служебных UUID. Чужие бонусы/штрафы не отменяются.

## Уничтоженный код: сначала выбор

Сначала отличите инцидент от предусмотренного [дестроя](organizational-levels.md#дестрой): недоступность находки другим командам по правилам этой механики сама по себе не требует исправления результатов.

Предложите вариант исключить уничтоженную единицу и снизить порог на одну. Автор выбирает `choice: "reduce-required-by-one"` или `"keep-results"`. Если он хочет другое правило, сначала точно сформулируйте его: текущий калькулятор поддерживает эти два варианта. Поле choice отсутствует → вопрос автору, без плана записи.

```json
{"id":"destroyed-level5","reason":"Уничтожен тигр2 на уровне 5","type":"destroyed-code","destroyedUnitId":"tiger","required":4,"choice":"reduce-required-by-one","units":[{"id":"elephant","answers":["слон1"]},{"id":"tiger","answers":["тигр2"]},{"id":"lion","answers":["лев3"]},{"id":"cat","answers":["кот4"]},{"id":"mouse","answers":["мышь5"]}]}
```

Здесь будет 3 живых единицы из оставшихся 4. Если исходно требовались все пять (`required:5`), будет 4 из 4. Aliases одного сектора — одна credit unit. Для команды `тигр2 → лев3 → слон1 → мышь5` при 4 из 5 момент не меняется; для `мышь5 → кот4 → лев3 → слон1` станет по `лев3`. При всех пяти кодах `тигр2` последним переносит прохождение на последний живой код; если он был раньше, время не изменяется.

Выбранная политика применяется ко всем включённым командам, включая введших код до уничтожения. Интервал/состав иной политики нужно согласовать, а не незаметно отфильтровать команды по моменту повреждения. При нулевом новом пороге или недостатке живых вводов нужны уточнения. Мониторинг не является доказательством виновности команды и не назначает штраф за уничтожение автоматически.

## Ошибка движка и фикс

Rule: `type:"wrong-answer"`, `fixedAt`, `affectedUnitIds`, `required`, `units`. Для затронутых units задуманные правильные строки до fixedAt засчитываются даже при `is_correct=false`. Остальные единицы требуют подтверждённого правильного ввода. Учитываются события на уровне между его началом и фактическим завершением; код после выхода с уровня не переносит прошлое прохождение.

Unit `{id,answers}` задаёт aliases одного логического ответа. Для [составняка](glossary.md#коды-и-обозначения), вводимого целой строкой, в `answers` указываются полные допустимые записи с согласованными разделителями. Отдельные вводы его частей не заменяют полный ответ.

Только если правило зачёта явно предусматривает совокупность отдельных вводов, используйте локальный расчётный формат `parts:[["первая часть"],["вторая часть","вариант второй"]]` и `ordered:true|false`; `answers:[]` допустим, если целой строки-ответа нет. Это формат калькулятора, а не автоматическое представление составняка в API. Для независимых частей берётся первое полное выполнение без повторного использования одного ввода, для последовательной цепочки — первое полное выполнение в указанном порядке. Дубли не дают новых частей, равные timestamps без доказанного порядка не устанавливают цепочку. Полное прохождение — первое выполнение всех/нужного числа units, а не первый ввод только исправляемого кода.

Строки сохраняются буквально. `comparison:"trim-casefold"` явно разрешает trim/lowercase; по умолчанию `literal`. Подмена е/ё, кириллицы/латиницы или похожих символов не выполняется. Историю правок и правила цепочки автор предоставляет отдельно: текущий редактор их не возвращает.

## Бонус

Rule: `type:"bonus"`, `bonusId` (или null для отсутствовавшего бонуса), `answers`, `intendedSeconds`. Список `creditedSeconds:{"team:123":20}` задаётся только при подтверждённом историческом начислении; иначе калькулятор ищет реальные суммы в corrections по bonus_id. Отсутствие такой записи не означает ноль. Для отсутствующего начисления явно подтвердите 0. Размер 20 вместо 120 даёт дополнительные 100 секунд один раз на получателя, независимо от повторных вводов.

Доступность бонуса с ограничениями задаётся подтверждённым `fromAt`/`toAt`; сегодняшняя настройка не доказывает историческое окно. Для отсутствовавшего бонуса возможен `source:"main"`, с `acceptUnrecognizedInputs:true` — только после подтверждения автора, что эти непринятые строки нужно засчитать. Когда ввода в доступных источниках нет, команда показана без предлагаемой записи с явным пояснением; если автор заявляет потерянные вводы, нужны дополнительные доказательства. Штраф на избыточный бонус требует подтверждения итоговой таблицы наравне с бонусами.

## Слёт/отмена

Rule: `type:"cancelled-level"`, `cutoff`, `participants`, `rosterConfirmed:true`, после решения автора `choice:"average" | "dismiss" | "keep-results"`. Сначала запросите расчёт без choice: он покажет M/N на cutoff и потребует решения. Более половины обычно означает среднее непрошедшим; менее половины — снятие; ровно 50% уточняется. Обычай не становится автоматическим решением.

Доноры — нормальные прохождения (`pass_type_id=0`) до cutoff. Снятие и таймаут не доноры. Знаменатель — подтверждённый состав команд игры, не число пользователей/строк мониторинга и не только дошедшие до уровня. Непрошедшие и не дошедшие остаются видны; отсутствие исходного времени не заменяется нулём.

`mean = sum(rawSeconds)/donorCount`. Для непрошедших `delta = targetRawSeconds - oldRawSeconds + alreadyIncidentAward`. Отрицательное delta → бонус, положительное → штраф. При среднем причина записи строго `Среднее время на уровне {номер}`. При 0 доноров среднего нет. Нормально прошедшим до cutoff ничего не меняется. Снятие — отдельное действие dismiss, которое входит в подтверждаемый план, а не бонус всем на выдуманное время.

Если уровень уже помечен снятым, сначала согласуйте его восстановление: корректировка длительности снятого уровня не заменяет это решение. Текущий процесс не возвращает уровень автоматически. После явно разрешённого восстановления получите свежие evidence и таблицу.
