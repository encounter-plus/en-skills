# Приоритет экранов для авторского UI

Перед проектированием определите поверхность (задание или анонс), тип игры и явно заданные автором целевые устройства. Для выбора приоритета используйте тип игры, а не порядок прохождения уровней: штурмовая последовательность сама по себе не означает тип «Мозговой штурм». Если тип неизвестен, уточните его у автора.

| Поверхность и тип игры | Приоритет | Как проектировать |
| --- | --- | --- |
| Скрипт задания: «Мозговой штурм» | Desktop first | Сначала продумайте работу на широком экране с мышью и клавиатурой; затем адаптируйте интерфейс для телефона. |
| Скрипт задания: остальные типы, включая «Схватку» и «Точки» | Mobile first | Сначала спроектируйте узкий экран и сенсорный ввод; затем расширяйте компоновку для desktop. |
| Анонс игры, включая его скрипты: любой тип игры | Mobile и desktop обязательны | Содержание и все действия должны работать на обеих поверхностях; тип игры не отменяет эту проверку. |

First определяет порядок проектирования и основной сценарий использования, а не отказ от второй платформы. Если автор явно задал другой приоритет, следуйте ему и зафиксируйте это в результате.

## Проверка результата

Проверяйте читаемость, размещение элементов, ввод и основные действия на узком и широком экране. Управление должно работать касанием, мышью и клавиатурой; существенные действия и сведения доступны без hover. Проверьте отсутствие непреднамеренной горизонтальной прокрутки и перекрытия полей экранной клавиатурой на доступном устройстве. В отчёте укажите приоритет, размеры экранов, способы ввода и непроверенные сценарии.

Для задания используйте [настоящую /preview Encounter и отдельный EN+ bridge](script-harness.md). Анонс — это авторский HTML-блок на странице игры `/games/{gameId}`, а не отдельная страница. Проверяйте его внутри страницы игры на mobile и desktop, а для приложения — в полном описании игры. Успешный тест в gameplay не подтверждает работу анонса. Доступность `window.EN`, селекторов и других API на этой поверхности устанавливается отдельно по [контракту и ограничениям](scripting-contract.md).

## Повторное использование

Этот документ — единый источник правила для скиллов авторского UI. Скилл game-announcement использует его вместе с [процессом создания анонса](announcement-workflow.md) и [моком страницы игры](announcement-harness.md). Таблицу приоритетов в скиллах не дублировать.
