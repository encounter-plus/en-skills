# Перенос по короткому запросу

Для плана, создания и проверки результата используй [общий контракт импорта](import-plan.md).

Для игрового уровня применяй [правило наличия подсказок и исключения](hints.md#назначение): почти всегда нужны подсказки; пустые ячейки источника не разрешают молча пропустить их. Учитывай установленную роль заглушки, дохода, доезда, подуровня или очень короткого уровня и явные решения автора.

Этот процесс применяется, когда автор просит найти материал по ссылке и создать или заполнить уровни. Краткий запрос задаёт результат; технический план, обнаружение листов, выбор операций и проверку готовит агент. Пользователь не обязан знать имена инструментов, ID листов или порядок вызовов.

1. Используй выбранную host игру, если другая цель не указана; проверь её домен, ID и текущие уровни чтением. При конфликте целей уточни игру. Похожий существующий уровень сначала прочитай и сравни: создание дубликата и замена содержимого не следуют из просьбы о переносе.
2. Выполни [чтение источника](document-reading.md). Обнаружь состав всей книги один раз. Для выбранного уровня полностью вычитай сам лист, сводку порядка и непосредственно связанные материалы; остальные листы классифицируй по реестру и релевантности. Для переноса всей игры дочитай все игровые части. Продолжай сохранённые результаты по курсорам, а не загружай книгу заново. Поиск «с баллонами и диалогами» — поиск по смыслу в основном варианте; резервные варианты учитывай отдельно. При двух равноправных кандидатах покажи различие и задай один вопрос о выборе.
3. Составь внутреннюю карту «источник → поле/сущность → проверка». Явные уточнения автора имеют приоритет над таблицей. Формулировки для игроков можно написать по его просьбе, сохраняя заданный смысл; коды, диалоги, HTML и скрипты из источника переноси буквально. ФО задаёт отображаемый формат ответа, а не разрешение изменять исходные коды. Различай альтернативные ответы одного сектора, обязательные секторы и необязательные бонусы. Для бонуса свяжи точный код, награду с единицами и соответствующий текст после выполнения.
4. Проверь [брифинг и уровень 0](import-workflow.md#брифинг-и-уровень-0), включая последнее уточнение автора о переносе текста. Раздели неизвестное и намеренно отложенное. «Создай бриф, текст позже» разрешает пустой текст этого уровня, без выдуманного задания и кодов. Это не повод проводить интервью о тексте. Для новых уровней сначала прочитай поддерживаемые настройки/шаблон движка. Название, текст, условия прохождения, секторы с ответами и порогом, автопереход со штрафом, подсказки с таймингом, бонусы с содержанием и наградами должны быть определены по источнику или ответам автора до подтверждения; для неуказанного штрафа за автопереход действует [правило нулевого штрафа с исключением для этой же игры](import-workflow.md#неуказанный-штраф-за-автопереход). Молчание источника о подсказках или времени не означает «нет»: задай один короткий блок вопросов о недостающем. Штатными можно оставить лишь не затронутые запросом технические настройки, не определяющие механику. Значимые для механики неизвестные (например, отсутствующая награда или неясное соответствие кода диалогу) требуют одного предметного вопроса с контекстом. Независимую подготовку продолжай. Не проси повторять уже известные сведения и не проводи анкету по всем возможным полям.
5. Подготовь полный объём запрошенных изменений, включая порядок: например, бриф перед игровым уровнем. В host с единым подтверждением представь один план для всего запроса. Сводка короткая: что создаётся, сколько сущностей, как проходит уровень, какие ограничения остаются. Точные тексты, коды и операции доступны в «Подробнее», а не занимают основной чат. Выбор инструментов и ссылки на ещё не созданные ID формирует агент. Подтверждение host — окончательное согласование этой версии; отдельное текстовое «да» перед той же кнопкой не требуется.
6. После подтверждения выполни все шаги, затем перечитай сохранённые сущности. Сверь порядок и названия уровней, задание, ответы и их привязки, условие завершения, каждый бонус: код, награду, единицы и диалог. Успех создания уровня не завершает перенос его содержимого. При неизвестном исходе установи фактическое состояние до продолжения и не повторяй запись вслепую. Если host остановил выполнение, сообщи проверенные выполненные шаги и конкретный остаток.

Пример трактовки: «создай бриф (текст позже) и игровой уровень с баллонами; коды открывают бонусы; ФО: слово; ввод в сектор унитаз, туалет» означает два уровня в указанном порядке, пустой бриф и один сектор игрового уровня с двумя альтернативными ответами `унитаз` и `туалет`. Это не строка с запятой и не два обязательных сектора. Количество бонусов, их коды, награды и диалоги устанавливаются по текущему источнику; числа и ответы из предыдущих задач не подставляются. Если документ противоречит явно заданным ответам, применяются ответы автора, а расхождение отмечается в деталях. Если роль запятой неоднозначна в конкретном формате, уточни её.

Перед завершением сравни исходный запрос и карту обязательных полей с фактически прочитанным результатом. Если пропущено однозначное согласованное поле, продолжай заполнение и сверку; при неизвестном исходе сначала сверяй состояние. Ошибка одного плана не разрешает согласовать частичную основу под видом полного переноса. После успешного подтверждения пользователь не должен писать «продолжай» для запуска остальных шагов.

Завершение: все запрошенные сущности записаны и сверены либо назван конкретный блокер; пользователь получил ID/ссылки, количества и непроверенные части. Отдельно различай проверенную настройку завершения и фактическое прохождение игроком: чтение настроек не доказывает игровой runtime.
