# en-skills

Набор скилов для авторов игр Encounter — «Схватки» и «Точек». Он помогает AI-ассистенту подготовить сценарий и анонс, придумать коды, вычитать задания, сверить фотографии и перенести согласованные материалы в движок.

Скилл — это инструкция для ассистента: что уточнить у автора, какие правила проверить и в каком виде выдать результат. Вместе со скиллами поставляются справочники и программные инструменты для проверок. Их можно использовать в агентном приложении или собственном боте.

Для работы с текстом достаточно скиллов и ваших материалов. Чтение закрытых документов, запись в Encounter, просмотр страниц и обработка изображений зависят от инструментов и авторизации в вашем приложении. Установка скиллов сама по себе не подключает аккаунты. Изменения в игре согласуются с автором.

Google Docs/Sheets читаются по открытой ссылке или в браузере с доступом пользователя. Для редактирования используйте навык `google-documents`: агент покажет правки, спросит одобрение и только после ответа внесёт их через браузер. Настраивать Google OAuth не нужно.

Например, можно сначала придумать уровень через `level-author`, затем проверить сценарий через `game-audit`, а после согласования подготовить перенос через `game-import`.

## Установка

### Поручить агенту

Скопируйте сообщение в чат вашего агента:

```text
Установи мне en-skills по этой инструкции:
https://raw.githubusercontent.com/encounter-plus/en-skills/HEAD/docs/install.md
Если установка через npx skills не получится, используй ручное копирование из инструкции. Проверь, что скиллы доступны, и покажи пример вызова.
```

[Открыть инструкцию установки](https://github.com/encounter-plus/en-skills/blob/HEAD/docs/install.md). Если работаете с локальной копией репозитория, можно написать: «Установи мне en-skills по инструкции docs/install.md из этого репозитория».

Если репозиторий недоступен агенту, передайте ему локальный файл инструкции вместе с checkout или архивом проекта.

### Установить самостоятельно

Нужны Node.js 24+ с npm и Git. Из каталога, где хотите сохранить исходники:

```sh
git clone https://github.com/encounter-plus/en-skills.git
cd en-skills
npm ci
npm run build:skills
npm run validate:skills
npx skills add ./dist/skills --skill '*' --global --copy
```

В последней команде выберите своё приложение. Для установки без выбора приложения добавьте `--agent codex` или `--agent claude-code`. Флаг `--global` делает скиллы доступными во всех проектах пользователя. Установка в один проект и другие клиенты описаны в [инструкции](https://github.com/encounter-plus/en-skills/blob/HEAD/docs/install.md).

Устанавливайте весь набор: `game-author` помогает выбрать нужный скилл, но не заменяет остальные. Если нужен один процесс, вместо `'*'` укажите, например, `game-audit`.

Если `npx skills` не работает, скопируйте целые папки из `dist/skills` в каталог скиллов приложения — вместе с `references/`, `scripts/` и другими вложенными файлами. Для Codex это `~/.agents/skills`, для Claude Code — `~/.claude/skills`. Пошаговые команды для Windows и macOS/Linux есть в [ручной установке](https://github.com/encounter-plus/en-skills/blob/HEAD/docs/install.md#3-резервный-способ-ручное-копирование).

**Не копируйте исходные папки из `skills/`:** они ссылаются на общие справочники вне своих каталогов. Сборка `dist/skills` делает каждый скилл самостоятельным.

## Как пользоваться

Откройте чат, приложите сценарий, фотографии или ссылку на документ и опишите задачу. Если скиллы ещё не появились, начните новую сессию приложения.

Можно вызвать скилл явно:

```text
$game-audit Проверь приложенный сценарий: логика, подсказки, тайминги и формат ответов.
```

В Codex CLI/IDE используется `$имя-скилла`, в Claude Code — `/имя-скилла`. Например, `/game-audit Проверь этот сценарий`. Это сообщение в чате, а не команда терминала. В других клиентах используйте их меню скиллов или напишите: «Используй game-audit для проверки сценария».

Можно написать обычную просьбу из таблицы ниже: агент подбирает скилл по смыслу. Если выбрал не тот, укажите имя явно. Синтаксис клиентов: [Codex](https://learn.chatgpt.com/docs/build-skills), [Claude Code](https://code.claude.com/docs/en/skills).

### Работа над игрой с game-author

`game-author` — общая точка входа: агент уточняет замысел и текущее состояние игры, помогает выбрать следующий шаг и подключает подходящий скилл — например, `level-author` для создания уровня или `game-audit` для проверки сценария. Согласованные результаты сохраняются в папке игры, чтобы следующий чат мог продолжить работу.

Для каждой игры используйте отдельную папку. Можно начать с запроса:

```text
Используй game-author. Подготовим новую игру «Обсерватория» в этой пустой папке.
Создай рабочую структуру по шаблону скилла, уточни замысел и предложи первые задачи.
```

Для создания файлов агенту нужны инструменты работы с файлами и доступ к выбранной папке. Одна установка скилла файлы игры не создаёт.

При инициализации в корне папки игры появляются:

| Файл или папка | Что хранится |
| --- | --- |
| `AGENTS.md` | Инструкции агенту: как читать и обновлять память игры |
| `GAME.md` | Название, замысел, ограничения, движок и известные идентификаторы игры |
| `decisions.md` | Подтверждённые решения автора и история их изменения |
| `tasks.md` | Текущие авторские задачи, ближайшие согласованные шаги и блокеры |
| `sources/` | Исходные документы, фотографии и снимки данных движка |
| `levels/` | Материалы игровых уровней; отдельные каталоги заполняются по мере работы |
| `artifacts/` | Подготовленные HTML, изображения и другие результаты |
| `.en-agent/project.json` | Технический идентификатор папки и версия шаблона |

`tasks.md` описывает работу автора, например «проверить ответы уровня», а `levels/` содержит сами задания для игроков, ответы и подсказки. Подробности задачи хранятся рядом с материалами; в текущем списке остаётся короткая запись с ID и ссылкой.

По мере накопления работы агент создаёт `planning/backlog.md` для предложений и отложенных задач, а закрытые задачи переносит с результатом в `archive/tasks/YYYY-MM.md`. Эти файлы появляются только при необходимости. В новом чате агент читает `GAME.md`, `decisions.md` и текущий `tasks.md`, затем материалы выбранной задачи. Backlog открывается при планировании, архив — для поиска конкретной истории, поэтому весь список когда-либо выполненных работ не загружается каждый раз.

После согласованных изменений агент обновляет материалы, решения и статусы задач. Инициализация предназначена для новой пустой папки; повторный запуск и обновление скиллов сохраняют существующие файлы игры. Чаты хранятся в приложении, а переносимая память — в папке игры. Подробнее: [структура и правила памяти игры](knowledge/game-workspace.md).

При проверке кодов исходное написание сохраняется. Неоднозначный вариант вроде `конь6` → `кон66` предлагается как дополнительный ответ для согласования.

Разделяйте изображения для задания игрокам и авторские фото локации/отписки кодов. Для первых рекомендуются `sources/task-assets/` или `levels/<id>/assets/`, для вторых — `sources/photos/` или `levels/<id>/photos/`. `game-author` и `check-code-photos` используют одни авторские исходники; они не попадают в задание автоматически. Можно указать другую существующую папку или отправить фото прямо в чат; агент уточнит неизвестный источник или назначение. Подробнее: [общий контракт изображений и фотографий](knowledge/game-workspace.md#фотографии-для-проверки-кодов).

## Как сообщить о проблеме или предложить улучшение

Посмотрите [существующие issues](https://github.com/encounter-plus/en-skills/issues). Если подходящей нет, [создайте issue](https://github.com/encounter-plus/en-skills/issues/new).

Для ошибки укажите приложение и ОС, имя скилла, ваш запрос, шаги воспроизведения, ожидаемый и фактический результат. Приложите текст ошибки или небольшой обезличенный пример. Для предложения опишите задачу автора и результат, который хотите получить. Пароли, токены, личные данные и материалы ещё не сыгранных игр замените вымышленными примерами.

## Как предложить изменения через PR

1. Сделайте fork репозитория и создайте отдельную ветку для своей правки.
2. Измените исходники: инструкции скиллов находятся в `skills/`, правила и справочники — в `knowledge/`, документация проекта — в `docs/`.
3. Сохраняйте ссылки скиллов на общие справочники. `authoring-guide.md` и `code-marking.md` — исходники правил; сохраняйте стабильные ID и комментарии области действия. Файлы `dist/` генерируются сборкой, вручную их не редактируют.
4. Выполните проверки из корня проекта:

   ```sh
   npm ci
   npm run build:skills
   npm run check
   git diff --check
   ```

5. Опубликуйте ветку в своём fork и откройте [Pull Request](https://github.com/encounter-plus/en-skills/compare). Опишите проблему, что изменилось для пользователя, как проверили результат; добавьте ссылку на issue, если она есть.

Используйте синтетические примеры. Тесты не должны менять реальные игры или запускать внешние авторские скрипты. Дополнительные проверки для изменений MCP и npm-поставки описаны в [руководстве разработчика](https://github.com/encounter-plus/en-skills/blob/HEAD/docs/maintenance.md).
