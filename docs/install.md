# Установка en-skills: инструкция для агента

Цель: установить выбранные скиллы Encounter в приложение пользователя и проверить их самостоятельность. Выполняй эту инструкцию, когда пользователь просит установить или обновить en-skills. Обычное чтение файла не является запросом на установку.

## 1. Определи место установки и подготовь поставку

Используй приложение и область установки из запроса пользователя. Если приложение известно из текущей среды, используй его. Если область не задана, устанавливай для текущего пользователя; если приложение определить нельзя, уточни его. По умолчанию устанавливай весь набор, поскольку `game-author` обращается к другим скиллам.

Проверь, какие одноимённые скиллы уже установлены. Перед заменой сохрани их полные резервные копии вне сканируемого каталога skills. Учитывай символические ссылки: сохрани содержимое их целей, а заменяй только выбранную установку. Не затрагивай остальные скиллы и настройки приложения.

Источник проекта: https://github.com/encounter-plus/en-skills. Используй предоставленный пользователем checkout или архив, если он уже есть. Иначе клонируй репозиторий в новый каталог:

```sh
git clone https://github.com/encounter-plus/en-skills.git
cd en-skills
```

Если источник недоступен, сообщи ошибку и попроси доступную копию репозитория или архив собранных скиллов. Не подменяй источник другим одноимённым пакетом. Имя npm-пакета — `@encounter-author/tools`, но текущий `package.json` помечен `private: true`; установка из npm registry не является предусмотренным здесь способом.

Для сборки из исходников нужны Node.js 24+ и npm. Проверь `node --version` и `npm --version`, затем выполни из корня checkout:

```sh
npm ci
npm run build:skills
npm run validate:skills
```

Продолжай после успешной сборки и валидации. Источник установки — **абсолютный путь к `dist/skills`**. Каждый его непосредственный подкаталог содержит `SKILL.md` и все свои зависимости. Копирование исходного `skills/` теряет общие справочники `../../knowledge/`.

Если пользователь предоставил готовую сборку, проверь её содержимое и переходи к установке без npm. Если Node.js или сеть недоступны, ручной способ работает с готовой сборкой; он не заменяет сборку исходников.

## 2. Основной способ: npx skills

Из корня собранного checkout посмотри состав поставки:

```sh
npx skills add ./dist/skills --list
```

Установи набор для выбранного приложения. Пример для Codex, доступного во всех проектах пользователя:

```sh
npx skills add ./dist/skills --agent codex --skill '*' --global --copy -y
npx skills list --global --agent codex
```

Для Claude Code замени `codex` на `claude-code`. Другие идентификаторы: `cursor`, `gemini-cli`, `github-copilot`, `opencode`, `windsurf`, `hermes-agent`, `openclaw`; сверяй поддержку с [документацией Skills CLI](https://github.com/vercel-labs/skills). Не используй `--all`: он выбирает также все приложения, а не только все скиллы.

Для одного скилла замени `'*'` на его имя. Для установки в конкретный проект перейди в **целевой проект**, убери `--global` и передай абсолютный путь к собранной поставке:

```sh
npx skills add "<абсолютный-путь-к-en-skills>/dist/skills" --agent codex --skill '*' --copy -y
npx skills list --agent codex
```

Заменяй значения в угловых скобках реальными путями. `--copy` выбирает копирование файлов. `-y` используй только после определения целевого приложения, набора и области установки.

Прямой `npx skills add encounter-plus/en-skills` подходит только для публикации, содержащей самостоятельные скиллы со справочниками. Исходный checkout с внешними ссылками на `knowledge/` устанавливай через сборку, как описано выше.

Если CLI недоступен, завершился ошибкой или установил неполный набор, запиши причину и переходи к ручному способу. При частичной установке сначала проверь фактически созданные каталоги, чтобы избежать дубликатов.

## 3. Резервный способ: ручное копирование

Ручная установка выполняется без `npx skills`. Возьми **целые каталоги** из проверенного `dist/skills`: `SKILL.md`, `references/`, `scripts/` и любые другие вложенные файлы. Не меняй внутреннюю структуру.

| Приложение | Для пользователя | Для одного проекта |
| --- | --- | --- |
| Codex | `~/.agents/skills/` | `<проект>/.agents/skills/` |
| Claude Code | `~/.claude/skills/` | `<проект>/.claude/skills/` |

`~` означает домашний каталог пользователя, на Windows обычно `C:\Users\<имя>`. Для другого приложения сначала выясни его каталог скиллов по документации или действующей конфигурации. Пути и обнаружение: [Codex](https://learn.chatgpt.com/docs/build-skills), [Claude Code](https://code.claude.com/docs/en/skills).

Команды ниже рассчитаны на первую установку: при совпадении имени они останавливаются до копирования. Для обновления сначала сохрани резервную копию и вынеси старые выбранные каталоги за пределы каталога skills; затем скопируй новые. Не сливай новую версию со старой: в ней могут остаться удалённые файлы.

### Windows PowerShell

Запусти из корня en-skills. Пример для Codex; для Claude Code замени `.agents/skills` на `.claude/skills`. Для проекта задай `$skillDestination` абсолютным путём из таблицы.

```powershell
$skillSource = (Resolve-Path -LiteralPath './dist/skills').Path
$skillDestination = Join-Path ([Environment]::GetFolderPath('UserProfile')) '.agents/skills'
$skillFolders = @(Get-ChildItem -LiteralPath $skillSource -Directory)
if ($skillFolders.Count -eq 0) { throw 'Сборка не содержит скиллов' }
foreach ($skillFolder in $skillFolders) {
    if (Test-Path -LiteralPath (Join-Path $skillDestination $skillFolder.Name)) {
        throw "Уже установлен $($skillFolder.Name): сначала сохраните резервную копию"
    }
}
New-Item -ItemType Directory -Path $skillDestination -Force | Out-Null
foreach ($skillFolder in $skillFolders) {
    Copy-Item -LiteralPath $skillFolder.FullName -Destination $skillDestination -Recurse -ErrorAction Stop
}
Get-ChildItem -LiteralPath $skillDestination -Directory
```

### macOS / Linux (Bash)

Запусти из корня en-skills. Для Claude Code замени `.agents/skills` на `.claude/skills`, для проекта — укажи абсолютный путь назначения.

```bash
(
  set -e
  skill_source="$PWD/dist/skills"
  skill_destination="$HOME/.agents/skills"
  shopt -s nullglob
  skill_folders=("$skill_source"/*/)
  if [ "${#skill_folders[@]}" -eq 0 ]; then
    printf '%s\n' 'Сборка не содержит скиллов' >&2
    exit 1
  fi
  for skill_folder in "${skill_folders[@]}"; do
    skill_name=$(basename "$skill_folder")
    if [ -e "$skill_destination/$skill_name" ] || [ -L "$skill_destination/$skill_name" ]; then
      printf 'Уже установлен %s: сначала сохраните резервную копию\n' "$skill_name" >&2
      exit 1
    fi
  done
  mkdir -p "$skill_destination"
  for skill_folder in "${skill_folders[@]}"; do
    cp -R "${skill_folder%/}" "$skill_destination/"
  done
)
```

Если приложение принимает только ZIP, подготовь архив отдельного собранного скилла с папкой `<имя>/SKILL.md` и всеми её файлами. Пользователь загружает его через поддерживаемый интерфейс приложения; локальное копирование само по себе не устанавливает скилл в облачный чат.

## 4. Проверь установку

Проверяй **каталог назначения**, а не только исходный checkout:

1. Сравни список установленных имён с выбранными папками сборки. Для полного набора должны совпасть все имена, обнаруженные в `dist/skills`.
2. У каждого скилла проверь наличие `SKILL.md`, состав файлов и соответствие их содержимого сборке. Убедись, что относительные Markdown-ссылки, включая ссылки внутри справочников, разрешаются в границах установленного скилла. Ссылки на исходный `../../knowledge/` означают неправильную поставку.
3. Проверь обнаружение скиллов в целевом приложении. Если доступен только файловый доступ, честно укажи: файлы проверены, обнаружение клиентом ещё не подтверждено. Предложи новую сессию или перезапуск, если список не обновился.
4. Покажи безопасный первый запрос: «Используй game-audit: проверь вымышленное задание “Сколько будет 2 + 2?”, ФО: число, ответ: 4». В Codex CLI/IDE можно написать `$game-audit`, в Claude Code — `/game-audit`.

Запрос на установку разрешает установку скиллов, но не изменения реальной игры. Подключение Encounter, учётные данные и журналы операций принадлежат приложению пользователя. Google Docs/Sheets используют браузер приложения; редактирование требует одобрения показанных правок. Подключай CLI/MCP только при отдельной потребности: [инструменты и интеграции](tools-and-integrations.md), [MCP runtime](../knowledge/mcp-runtime.md).

В итоговом сообщении перечисли приложение, область и путь установки, установленные имена, использованный способ, результат проверок и пример вызова. Если использован ручной способ, укажи причину. Сообщай об успехе только в пределах выполненных проверок.

## 5. Обновление

Для локальной поставки получи актуальные исходники, сохранив пользовательские изменения, повтори сборку и валидацию, затем установку с резервной копией прежних скиллов. Для ручных копий также повтори проверку каталога назначения. Команда `npx skills update` предназначена для отслеживаемых CLI источников; ручные копии обновляются повторным копированием.
