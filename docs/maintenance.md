# Сопровождение en-skills

Этот документ предназначен для разработчиков пакета. Пользовательские процессы находятся в `skills/` и `knowledge/`; команды сборки, проверки самого проекта и обновления снимков в переносимые справочники не включаются.

## Подготовка и проверки

Из корня репозитория выполните `npm ci`, затем `npm run check`. Отдельная проверка автономной npm-поставки: `npm run test:package`.

Для MCP выполните в `runtime/` команды `pnpm install --frozen-lockfile` и `pnpm validate`. Сборка создаёт `runtime/dist/server.mjs` и `runtime/dist/cli.mjs`. Проверка манифестов из корня: `node tooling/validate-plugin.mjs`.

Live smoke не входит в обычные проверки: `pnpm --dir runtime contract:live` обращается к отдельной тестовой игре. Запись требует явного `--allow-write` и `ENCOUNTER_LIVE_CONTRACT_ACK=TEST_GAME_ONLY`. Синтетические тесты не подтверждают production-контракт.

## Обновление снимка EN+

Обычная сборка и проверка задания используют готовый снимок. Для его обновления укажите выбранный checkout приложения:

```text
node tooling/snapshot-webview.mjs --enplus-root "<en-plus-kotlin>"
```

Для RN добавьте `--framework react-native`; без него собирается Kotlin. Оба профиля поставляются только в обфусцированном виде: минифицированный injected runtime, упакованный renderer без source maps. Это затрудняет чтение, но не является шифрованием. Сборщик читает TypeScript entrypoint и стили, компилирует runtime через esbuild и сохраняет manifest. Установленный CLI может создать отдельный снимок: `en-webview-snapshot --enplus-root "<en-plus-kotlin>" --out ./my-snapshot`. После обновления проверьте поведение и покрытие стилей стенда.

## Встраивание библиотеки

Потребитель может импортировать функции ядра из `@encounter-author/tools`, без запуска CLI. Интеграция с ботом, моделью, хранилищем пользователей и секретов принадлежит приложению-потребителю. Пример подключения находится в [инструментах и интеграциях](tools-and-integrations.md#использование-отдельным-ботом).

В документации `en-skills/`, `en-author/`, `encounter-api-sdk/`, `en-plus-kotlin/` и `cityproject/` обозначают корни соответствующих репозиториев. Параметры вида `<en-skills>` заменяются фактическим путём выбранного checkout; фиксированных каталогов рабочей машины нет.

## Проверка переносимых ссылок

После npm run build:skills выполните npm run validate:skills. Проверяются исходники и все три поставки: файлы, якоря (включая кириллицу и HTML id), определения reference-ссылок, достижимость knowledge и точное соответствие текущим исходникам. Упомянутые переносимые ресурсы examples/docs/references/scripts оформляйте Markdown-ссылками; примеры в fenced code blocks не считаются зависимостями. JSON-примеры локального входа находятся в переносимом knowledge/local-data-contract.md, поля анонса — в knowledge/announcement-api-contract.md.

Для необязательной проверки внешних источников: node tooling/validate-skills.mjs --external. Она выводит HTTP-статус либо ошибку доступа с таймаутом; 403 и сетевые ошибки не означают удаление страницы. Обычный check работает без сети.

## Проверка workflows

При изменении поведения обновите соответствующую пользовательскую страницу в docs/skills, карту game-author и сценарии оценки. Каталог определяется discoverSkills, отдельного реестра нет. npm run check проверяет согласованность каталога и структуру evals; реальный прогон модели и сравнение результатов выполняются отдельно по [протоколу evals](../evals/README.md). Механическую ошибку закрепляйте детерминированным тестом; смысловую ошибку оформляйте обезличенным воспроизводимым случаем с независимыми ожиданиями.
