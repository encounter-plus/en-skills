# Синтетические механики

Это абстрактные учебные данные, без названий, ответов, координат или ID реальных игр. Случаи зарегистрированы в `evals/cases.json`; их request — исходное описание автора, checks — критерии оценщика. Это eval-формат репозитория, не API-поля. Агенту передавайте request и artifacts без checks.

- `ordinary.game.json`, `replacement.game.json` — полный внутренний `GameDraft` schemaVersion 1, проверяется настоящим `parseGame`. В нём нет структурированных бонусов; расширять его произвольными полями нельзя.
- `effects.requests.json` — учебный список `{schema, body}`. Обёртка принадлежит eval, каждый `body` — отдельный wire request нового API по указанной модели, а не редактор уровня и не готовый план записи. Это фрагменты настроек, не доказательство доступности операции.
- `openapi-excerpt.json` — точные определения используемых моделей из снимка Swagger нового API. В нём указаны URL, дата снимка и SHA-256 полного upstream-файла. Источник в checkout SDK: `spec/upstream/swagger.json`; проверки работают по включённой копии и не требуют соседнего репозитория или сети.

`bonus_time: 7` и `timeout: 11` в wire-примере — намеренно сырые значения с неподтверждённой единицей: снимок спецификации её не описывает. Не объявляйте их минутами/секундами и не отправляйте в реальную игру. `life_time_sec: 600` имеет явно секундное имя, но порядок эффектов и включённость границы требуют проверки поведения. Типовая валидность DTO не доказывает спортивную корректность, выполнение скрипта или совместное закрытие секторов.

Автоматические тесты проверяют внутренний парсер, имена/типы полей DTO по снимку и согласованность учебного набора замен. Они не подменяют поведенческий прогон агента по критериям. Добавленные случаи пока являются корпусом, а не заявлением о пройденном моделью eval.
