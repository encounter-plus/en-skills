# Администрирование игры

Перед процессом примените [выбор движка и capabilities](../../knowledge/engine-capabilities.md): scope и поддержка каждой операции задаются host; unsupported поля и гарантии не выдумываются.

1. Определите домен, игру, объект и точное изменение. Прочитайте [административный контракт](../../knowledge/admin-contract.md); при правке нанесённого кода — [отписку кодов](../../knowledge/code-marking.md). Проверьте наличие авторизованного adapter; CLI получает снимки, библиотечный applyLevel выполняет явные пакетные записи уровня.
2. Для настроек игры прочитайте [полный контракт настроек](../../knowledge/game-settings.md): modern partial PATCH и legacy нативная форма имеют разные поля и типы. Используйте reviewed game-settings proposal; произвольный POST запрещён. Прочитайте свежий объект и его версию/возможности. Различайте ID и номер уровня; проверьте участников на уровне. Не подменяйте открытие статистики открытием оценивания.
3. Подготовьте before/after. Сохраняйте связанные поля, которые метод PUT может требовать целиком. Для времени установите единицы и базу отсчёта. Конкретная команда пользователя уже может разрешать запись; дополнительный вопрос нужен для отсутствующего существенного решения, а не для повторения разрешения.
4. Выполните только согласованные операции. Для modern level apply используйте base_version, учитывайте ограничение 200 операций и запрет массового изменения при игроках. 409 требует анализа причины; 207 требует учёта результата каждой операции. Для legacy используйте объявленные adapter preconditions/observed revision и read-back; server CAS не предполагается. Не повторяйте неопределённую запись вслепую.
5. Перечитайте изменённые значения и сверяйте с планом. Отчёт содержит применённое, неудавшееся, неизвестное и следующий конкретный шаг. Если adapter отсутствует, выдайте неприменённый план; для локальных черновиков доступны [отдельные команды](../../knowledge/local-tools.md).

Завершение: все операции имеют подтверждённый результат или явно неопределённый статус. Отсутствие ошибки инструмента не является доказательством сохранения нужного значения.

При необходимости данных внешнего сервиса прочитайте [доступные интеграции](../../knowledge/integrations.md), проверьте установленный runtime и credentials. Не выдавайте сырой снимок API за нормализованный сценарий или OCR за подтверждённое наблюдение.

Перед записью проверьте [live preflight](../../knowledge/live-game.md); если работа идёт через установленный MCP, прочитайте [его контракт](../../knowledge/mcp-runtime.md). Инструкции не предоставляют отсутствующих инструментов и не отменяют ограничения установленного adapter.

Если live-ограничение запрещает удаление, предложите безопасную альтернативу для текущего прохождения: дополнительный ответ при ошибочном коде, если движок это разрешает, либо текст сообщения организатора. Если причина ошибки неизвестна, обозначьте условие выбора. Альтернативу применяйте только в пределах уже данного разрешения; иначе сначала согласуйте её отдельно.
