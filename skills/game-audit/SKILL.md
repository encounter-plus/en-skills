# Аудит игры

1. Определите объём проверки, формат игры и состояние: черновик или игра с участниками. Получите сценарий, ответы, подсказки, тайминги и правила. Если доступна только часть, проверяйте её и перечислите пропуски.
2. Прочитайте [руководство автора](../../knowledge/authoring-guide.md). При незнакомых терминах используйте [модель Encounter](../../knowledge/encounter-domain.md). Для солянки прочитайте соответствующие форматы в [справочнике](../../knowledge/solyanka-formats.md); для подготовки нанесения — [советы по написанию кодов](../../knowledge/code-marking.md#советы-по-написанию-кодов), для сверки надписей с движком — [пробитие кодов по фото](../../knowledge/code-marking.md#пробитие-кодов-по-фото).
3. Проверьте все применимые пункты с ID: ok / finding / not-checked / not-applicable. Нужны доказательства, а не отметки по отсутствию ошибок в тексте. Рекомендации по полю неприменимы к чисто виртуальному уровню. Субъективный совет отделяйте от ошибки и авторской механики.
4. Проверьте наличие и ясность ФО в видимом задании по [единому справочнику форматов ответа](../../knowledge/answer-formats.md), сопоставьте с решением и принимаемыми ответами. При пропуске предложите явно указать ФО. Для координат в условии и ответах примените [рекомендацию по десятичным градусам](../../knowledge/answer-formats.md#координаты). Вычитайте текст, сохраняя ФО, коды, HTML/JS и намеренные искажения. Решите логические задания независимо, затем сопоставьте с авторским решением и проверьте дуали. Если авторского решения нет, обозначьте предел проверки.
5. Определите [роли подсказок](../../knowledge/hints.md) и проверьте их доступность для предусмотренного этапа. Для каждой, включая первую, выполните [проверку содержательного вклада](../../knowledge/hints.md#логика); дублирование уже известного отметьте как дефект. Проверьте единицы и базу отсчёта времени, число требуемых секторов, окна бонусов. Оценки времени поиска/доезда не выдавайте за замеры. При наличии en-skills CLI выполните [локальные проверки](../../knowledge/local-tools.md), затем дополните их смысловым аудитом.
Для проверки версий документа/отписки и смысловых дуалей прочитайте [содержательное ревью](../../knowledge/author-review.md). При сложных эффектах кодов, истекающих бонусах или повторном реквизите примените [проверку связей](../../knowledge/scenario-mechanics.md). Для проверки действий игроков, сочетаний механик и порядка прохождения используйте [игровые механики и организационные уровни](../../knowledge/organizational-levels.md), включая условия технических этапов и вопросы автора. При внешних источниках и зависимости от места прочитайте [полевые зависимости](../../knowledge/field-dependencies.md).

При пропуске этапа за штраф отдельно установите способ выхода и ручное либо автоматическое начисление: штраф сам по себе не задаёт АП или переход. Неизвестный механизм отметьте как непроверенный. Проверка полевого резерва охватывает и эквивалентность носителя, и доступ к исходному месту в часы игры: укажите известные дату осмотра и план повторной проверки с ответственным, а отсутствующие сведения — как непроверенные.

При предварительной выдаче материалов для участка с плохой связью свяжите место загрузки, разрешённый момент раскрытия задания и начало зачёта. Если последние два решения неизвестны, предложите условные варианты для согласования, а не безусловную инструкцию игрокам раскрыть всё заранее.

6. Отдельно сопоставьте сценарий с подтверждёнными требованиями автора по [двум осям ревью](../../knowledge/author-review.md#две-оси-проверки). Если замысел не предоставлен, обозначьте эту границу и продолжайте техническую проверку. Когда от неизвестного замысла зависит разрешение конкретного конфликта источников или настроек, задайте адресный вопрос автору: какое условие он подтверждает. Отметка «непроверено» не заменяет этого вопроса; до ответа не выбирайте настройку за автора.
7. Подготовьте [отчёт с покрытием правил и требований](../../knowledge/review-report.md). Выдайте приоритетные замечания: объект → правило → доказательство → влияние → исправление; приложите покрытие чеклиста и неразрешённые вопросы. Если пользователь просил исправления, подготовьте точные before/after и применяйте только доступным инструментом в пределах запроса. Отчёт об аудите сам по себе не меняет игру.

До проверки зафиксируйте выбранные уровни, доступные источники и пробелы. Проверка завершена, когда по каждому выбранному объекту известен результат применимых правил и подтверждённых требований либо конкретная причина невозможности проверки. Отчёт готов, когда каждое замечание связано с источником и предложением; прогноз опыта игрока отделён от проведённого плейтеста.

Завершение: каждый предоставленный уровень учтён; каждому применимому правилу назначен статус с основанием; исправления отделены от предложений, непроверенное явно перечислено.

Если для проверки нужны данные Encounter, Google или OCR, прочитайте [доступные интеграции](../../knowledge/integrations.md), проверьте установленный runtime и credentials. Не выдавайте сырой снимок API за нормализованный сценарий или OCR за подтверждённое наблюдение.

## Справочная база

Если значение термина влияет на вывод, уточните его по [глоссарию](../../knowledge/glossary.md); связи сущностей смотрите в [устройстве игры](../../knowledge/encounter-domain.md). Обозначения ФО хранятся только в [answer-formats.md](../../knowledge/answer-formats.md). Для советов по оформлению Google Docs/Sheets используйте [памятку автору](../../knowledge/scenario-authoring.md). Справочные определения отделены от порядка действий этого скилла.

При языковой вычитке примените [правила грамматики](../../knowledge/grammar.md). После определения формата используйте соответствующие ограничения: [Схватка](../../knowledge/game-type-encounter.md) или [Точки](../../knowledge/game-type-points.md). Инструкции не предоставляют отсутствующих инструментов и не отменяют ограничения установленного adapter.

При проверке написания имён, названий и дат используйте [Википедию, инфобокс и варианты ответа](../../knowledge/wikipedia-answer-variants.md). Предлагайте алиасы с учётом ФО; не применяйте их автоматически.

При аудите изображений проверьте [вес, разрешение и возможность оптимизации](../../knowledge/image-optimization.md). Учитывайте слабую связь и суммарную загрузку; предложите облегчённые копии только с сохранением смысла задания. Гигарамы и другие задачи на мелкие детали требуют сохранения оригинала. Недоступные размеры помечайте как непроверенные.
