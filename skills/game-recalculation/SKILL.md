# Пересчёт после игры

1. Определите домен, игру и уровень. Если автор не сообщил причину, уточните её. Проверьте завершение игры; анализ текущей игры и её изменение — отдельная задача. Прочитайте [процесс и инструменты](../../knowledge/recalculation-workflow.md).
2. Получите полный мониторинг основных и бонусных ответов, статистику, состав участников, редактор уровня и уже начисленные корректировки через фактически доступные инструменты. Выберите adapter движка до запросов. Для legacy нужен cookie host, полный native roster с настоящим game-player ID и отдельный GameStat final-total источник: StatItems JSON не включает все ручные начисления. Не достраивайте неизвестные identity/timezone/coverage. Локальные опорные номера legacy-снимка не называйте server action IDs. Номер уровня отличается от DB ID. Непринятые вводы нужны для ошибочного кода до фикса. Неполный или закрытый мониторинг не означает отсутствие вводов.
3. Выберите соответствующую ветку в [правилах расчёта](../../knowledge/recalculation-rules.md). Для уничтоженного кода предложите вариант пересчёта, объясните последствия и получите выбор автора. Снижение порога на один не является обязательным правилом. Для слёта покажите количество и долю нормально прошедших на момент инцидента и уточните решение автора; ровно 50% требует отдельного правила.
4. Выполните расчёт инструментом/скриптом, сохранив формулу, исходные времена и action IDs. Для [составняка](../../knowledge/glossary.md#коды-и-обозначения) учитывайте полный ответ; при явно заданном зачёте отдельных вводов восстановите первое полное выполнение по [правилам расчёта](../../knowledge/recalculation-rules.md#ошибка-движка-и-фикс). Первый ввод одной части не равен прохождению. Числа и времена берите из результата выполнения, не вычисляйте в тексте ответа. При отсутствии полного runtime можно проверить среднее и разницы через [math_check.py](scripts/math_check.py); этот скрипт не восстанавливает мониторинг и не выставляет корректировки.
5. Покажите таблицу всех команд: исходное и целевое время/начисление, ранее выставленное по этому инциденту, бонус, штраф, причина и подтверждающие вводы. Отдельно перечислите доноров среднего, сумму, делитель и округление. Неопределённые строки сначала уточните. Предложите проставить корректировки по таблице и получите подтверждение именно этого плана. Причина для среднего: «Среднее время на уровне {номер}».
6. После подтверждения передайте неизменённый план исполняющему host. Модель не записывает себе approval через аргументы tools. Перечитайте источники перед применением; при изменении данных нужен новый расчёт и подтверждение. По [контракту SDK и записи](../../knowledge/recalculation-api.md) проверяйте каждую запись через read-back. Неопределённый POST не повторяйте. Итоговый отчёт перечисляет все строки, суммы, ID и verified/rejected/unknown/pending. Проверку записи и отражение итогов в статистике показывайте раздельно.

Скилл сам не предоставляет сетевые инструменты, shell или авторские права. Если host не умеет записывать, выдайте таблицу и точный неприменённый план. Повторное разрешение уже подтверждённой неизменённой таблицы не требуется.

Переход к расчёту требует достаточных исходных данных выбранного правила. Таблица готова к согласованию после учёта всех команд и неопределённых строк. Подтверждение начислений и отражение итогов в статистике завершаются отдельно; рассчитанная таблица без записи остаётся планом.
