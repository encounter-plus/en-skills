# Пробитие кодов по фото

Этот процесс проверяет авторские фото отписки кодов и связанные фотографии локации. Картинки и фотографии, предназначенные для задания игрокам, относятся к level-author; наличие на них текста или кода само по себе не делает их свидетельством отписки. В смешанном наборе выделите авторские фото для проверки, а неясное назначение уточните по общему контракту ниже. Отдельный общий план локации без кода сохраняйте как контекст, не считайте его ошибкой чтения.

Перед проверкой примените [общие с game-author правила хранения и получения фото](../../knowledge/game-workspace.md#фотографии-для-проверки-кодов). Используйте уже присланные фото или известную папку; если источник неизвестен, спросите путь либо предложите отправить фото в чат. Рекомендуйте сохранять исходники в папке материалов игры или конкретного уровня по этому контракту, чтобы оба скилла ссылались на одни файлы. Отдельный вызов check-code-photos не требует предварительного запуска game-author или создания папки игры.

1. Прочитайте раздел [пробитие кодов по фото](../../knowledge/code-marking.md#пробитие-кодов-по-фото). При неоднозначности префикса, АЧ или сектора используйте [глоссарий](../../knowledge/encounter-domain.md).
2. Получите исходные фото и их привязку к домену/игре/уровню/сектору. Объедините [кадры одной сцены](../../knowledge/code-marking.md#группы-кадров-одной-сцены-и-место-отписки): общий план/конечку, указание пальцем места и крупный план кода. Сохраните каждый файл и обоснование связи. Проверьте актуальность и отличите погашенные старые коды. Не выбирайте сектор только по похожести ответа в документе. Если код невозможно снять целиком, проверьте [составной код из нескольких фото](../../knowledge/code-marking.md#составной-код-из-нескольких-фотографий): сохраните части и подтвердите их порядок до сборки одного ответа.
3. Перед чтением проверьте ориентацию: фото из труднодоступного места может быть снято фронтальной камерой и сохранено зеркально. Двоеточие и метка в конце надписи вместо начала — повод проверить [зеркальное отражение](../../knowledge/code-marking.md#зеркальные-фотографии-и-фронтальная-камера) до вывода о нечитаемости или расхождении.
4. Основной способ — модель с image input: передайте ей исходное фото (при необходимости также увеличенные фрагменты), а не только результат OCR. В Codex/Claude используйте зрение модели хоста; для отдельного runtime доступен image-model adapter. Читайте независимо от ожидаемых кодов, сохраняйте буквальную строку, область, спорные символы и визуальные основания альтернатив. При невозможности прочитать ставьте unreadable. Google Cloud Vision OCR — только fallback при недоступности/технической ошибке image input; явно обозначьте его использование. Не заменяйте неоднозначное чтение уверенным ответом OCR и не запускайте fallback ради обхода отказа модели. При отсутствии обоих способов запросите более качественное фото/чтение автора.
5. Сравните фото, документ и движок. Читаемое актуальное фото — источник физической надписи. Документ объясняет исходное намерение и не исправляет фото задним числом. Различайте точное совпадение, расхождение, нечитаемость и неизвестную привязку.
6. Отдельно оцените альтернативное чтение, даже при совпадении основного кода с движком. Для каждого неоднозначного написания выполните [правило рекомендации мультиварианта](../../knowledge/code-marking.md#мультиварианты-при-неоднозначном-написании), сохранив исходный ответ. Проверьте коллизии с другими секторами и влияние на шифр/АЧ.
7. При доступном CLI можно [сравнить наблюдения и получить кандидаты](../../knowledge/local-tools.md). Эти команды не выполняют OCR и не записывают ответы. Выведите фото/область, сектор, буквальное чтение, документ, движок, предложение и основание. Для каждой подсказки о месте кода используйте одно короткое и точное предложение по [правилам описания места](../../knowledge/code-marking.md#группы-кадров-одной-сцены-и-место-отписки); сравните с авторской таблицей, а подробности проверки оставьте отдельно. Чистая проверка завершается этим отчётом; запись требует разрешённого изменения и реального административного инструмента.

Завершение: каждое фото имеет результат или явную причину неопределённости; связанные кадры объединены в группы со ссылками на оригиналы; для каждого кода указано место отписки либо «место по фото не установлено», подготовлена сводка расположений для будущей подсказки; для каждого визуально обоснованного альтернативного чтения рекомендован конкретный мультивариант либо отмечено, что он уже принимается; варианты не подменяют исходное чтение; применённые изменения подтверждены чтением из движка либо отмечены «не применено».

Подключение к Encounter, Google или OCR: прочитайте [доступные интеграции](../../knowledge/integrations.md), проверьте установленный runtime и credentials. Не выдавайте сырой снимок API за нормализованный сценарий или OCR за подтверждённое наблюдение.
