# Анонс игры

Перед процессом примените [выбор движка и capabilities](../../knowledge/engine-capabilities.md): scope и поддержка каждой операции задаются host; unsupported поля и гарантии не выдумываются.

1. Соберите название, тему, дату и время старта с часовым поясом, тип игры, формат участия, место или район, взнос, требования, снаряжение и ссылки. Используйте данные автора или доступный локальный снимок; неизвестные сведения уточните, не выдумывайте.
2. Прочитайте [правила анонса и постера](../../knowledge/announcement-workflow.md) и примените [общую политику авторского UI](../../knowledge/author-ui-policy.md). Анонс размещается внутри страницы игры `/games/{gameId}`. Для него обязательны mobile и desktop независимо от типа игры.
3. Подготовьте авторский HTML-фрагмент с локально ограниченными CSS и, при необходимости, JavaScript. Для скриптов прочитайте [общие правила JavaScript](../../knowledge/scripting/common.md) и [ограничения исполнения в стенде анонса](../../knowledge/announcement-harness.md). Подтвердите выполнение JS и зависимости на целевой поверхности и в выбранном runtime: gameplay runtime не доказывает поддержку скриптов или наличие jQuery в анонсе. Сохраняйте основные сведения доступными без взаимодействия. Контракт gameplay `window.EN` для анонса не предполагается. Инициализацию и обработчики ограничьте контейнером анонса.
4. Рекомендуйте пользователю отдельное превью `poster.png` (допустимы `poster.jpg` и `poster.gif`). Если доступна модель или инструмент генерации изображений, предложите сгенерировать постер. Создавайте его только по запросу или после согласия пользователя; существующий запрос на генерацию уже является согласием. Проверьте именно генерацию изображений у выбранной host/model: image input и OCR не означают генерацию. Если генерация недоступна, попросите пользователя прислать картинку для постера; ТЗ можно приложить как помощь, но оно не заменяет этот запрос. Состав и проверки описаны в общем руководстве.
5. Запустите [локальный мок страницы игры](../../knowledge/announcement-harness.md) с собственным HTML и сценарием всех интерактивных действий. Проверьте screenshots и report для обеих ширин, чтение текста, касание/клавиатуру, загрузку ресурсов и отсутствие переполнения. Исправьте выявленные дефекты. Проверку полного описания в приложении и живой страницы выполняйте отдельно, когда они доступны.
6. Отдайте HTML, ресурсы, статус предложенного постера и созданные по запросу файлы/ТЗ, инструкцию размещения, сценарий и результаты проверок. Разделяйте проверку мока, актуального сайта и приложения. Для публикации modern HTML используйте reviewed `encounter_propose_modern_announcement` или runtime `game-settings` с `descr` и явно выбранными `replace_nl_to_br`, `hide_game_descr`, `display_announcement`. Сверьте сохранённый текст и все флаги независимым чтением. Для supplied/generated изображения используйте host imageRef и `encounter_propose_modern_image_upload`; при poster:true проверьте отдельный poster_url после upload. `from_author_text` требует собственного подтверждённого контракта. Публикация и загрузка файлов выполняются только по запросу пользователя через подтверждённый контракт; создание анонса само по себе не означает публикацию.

Завершение: комплект пригоден для вставки в авторский блок страницы игры, проверен на mobile и desktop, статус постера и ограничения проверки явно указаны.
